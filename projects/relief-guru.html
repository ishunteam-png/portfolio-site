Relief Guru

Telegram-driven AI avatar video pipeline

A pharmacy-content business needed to publish AI avatar videos across YouTube, LinkedIn and Instagram, controlled from Telegram so non-developers can run it. I built that pipeline as seven coordinated n8n workflows. AI automation engineer, freelance, 2025–2026.

WHAT I BUILT

Why seven workflows. The first version (V1) was one giant n8n workflow with branching logic and “sub-functions” called by HTTP. It worked until the day it didn’t, and when it broke I couldn’t tell whether the failure was at intake, at script generation, at HeyGen, or at posting. V4 splits it into single-purpose webhooks — every step lives in its own workflow with its own logs.

WF1A — Intake Router. Telegram webhook into n8n. Admin whitelist by chat ID. Slash-command parser: /start, /help, /avatars, /voices, /templates, /new, /refresh_avatars, /refresh_voices, /status, /last, /company. Routes the request into the right downstream workflow with a stable run_id.

WF1B — Template + Script Generator. Take the brief, embed it with OpenAI text-embedding-3-small, query Pinecone against the templates namespace. Top-10 normally, top-100 if the operator gave a template hint, optional content_purpose filter. GPT writes the script against the closest template, the operator gets it back in Telegram for review.

WF2A — HeyGen Video Generation. The hairy one. Studio app posts a payload that, depending on which trigger fired, has the script under body.script, body.video_inputs[0].voice.input_text, body.text, or somewhere else. I wrote a Parse Studio Payload node that probes every reasonable path and, as a last-ditch, walks the whole payload looking for a string field with a name like script / text / input_text longer than 20 characters. If it doesn’t find one it hard-fails locally with the keys it saw — way better than letting HeyGen respond with an opaque “Bad request” 90 seconds later. Same approach for avatar_id and voice_id — guard on length ≥ 6 before HeyGen ever sees it.

Idempotency guard. n8n’s static workflow data stores run_id → timestamp for in-flight runs. A duplicate run_id within 30 minutes throws. Cleared lazily on every entry. Prevents Telegram retries (or the operator clicking a button twice) from spawning a second HeyGen render.

Sticky messages. Rather than spamming the chat with “recording… rendering… uploading… posted”, the workflow edits a single Telegram message in place. Same message_id for the lifecycle of the task. Looks like a progress bar in the chat.

HeyGen poll loop. 30-second cadence, max 40 attempts (~20 minutes). The script-cleaning step strips zero-width characters, smart quotes, HTML tags, markdown, and stage-directions in brackets/parens/braces. Truncates at the last sentence end below the 1500-character HeyGen cap.

WF2A↔WF2B — Approval Bridge. Once HeyGen is done, the operator approves in Telegram. Approval token is signed; no spoofing.

WF2B — Posting Core (native). Google Developer Console for Drive + YouTube; LinkedIn Developer Console for the LinkedIn post; Instagram via Meta API. Each posting is its own retry-safe sub-flow.

WF3 — Tracker Engine. Every step in every run logs a row with task_id, trace_id, log_type, workflow_id, step, status, state, embed_text. The embed_text (first 500 chars of the script if available, otherwise the topic) goes back into Pinecone so the next run can retrieve “what did we say about this topic last time”.

“V1 was one giant n8n workflow. Splitting it into seven single-purpose webhooks made every failure traceable to a single workflow ID.”
THE BITS THAT BIT ME

HeyGen used to fail silently because input_text was empty — the script was nested deeper in the payload than the parser knew about. After two of these I rewrote the parser to be paranoid and label each rev in the comments. Last revision is v2026-05-03 rev2.

Telegram’s Edit Sticky HTTP node returns its own {ok, result, …} object, which then becomes $json for the next code node. I lost ~30 minutes before realising the “script missing” error was actually the upstream context being shadowed. Now Clean Script explicitly reaches back to Code: Idempotency Guard and Code: Parse Studio Payload by name if $input doesn’t have what it expects.

Operationally, the seven-workflow split is more code but less rework. The whole point is that the next time posting to LinkedIn breaks at 11 pm, the operator sees “WF2B failed” in Telegram instead of a 60-node n8n trace.
